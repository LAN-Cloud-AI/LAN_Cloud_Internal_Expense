# 账号资产结构化与追加字段弃用设计

## 背景

账号资产目前只有显示名称、账号标识和归属人员等核心字段。资产所属的服务或平台混在显示名称中，难以单独筛选；页面同时暴露了不再需要的“追加字段”功能。

本设计将服务或平台抽取为固定的“资产标识”字段，简化新增流程，并以非破坏方式弃用追加字段。

## 目标

- 账号资产以四项核心信息清晰展示：显示名称、资产标识、账号标识、归属人员。
- 为管理员提供按资产标识筛选的能力。
- 将新增账号资产改为按需展开的菜单式流程。
- 让追加字段不再可用，同时保留已有记录，避免不必要的数据删除。
- 将当前线上清单按已确认的服务/平台口径完成回填。

## 非目标

- 不保存密码、验证码、令牌或其他凭据。
- 不删除 `account_field_definitions` 或 `account_field_values` 中的历史数据。
- 不自动执行远程 D1 migration、Cloudflare 部署或其他生产写入。
- 不改变员工只能查看本人账号资产的权限边界。

## 已确认的术语与回填口径

“资产标识”表示服务或平台名，而不是账号类型或账号值。显示名称保持现有文案，账号标识和归属人员保持原值。

| 现有显示名称模式 | 资产标识 |
| --- | --- |
| `…的OBS` | `OBS` |
| `… · GitHub ID` | `GitHub` |
| `… · GitHub 邮箱` | `GitHub` |
| `… · LeadsHunter 用户名` | `LeadsHunter` |
| `… · Obsidian` | `Obsidian` |
| `… · 兰芯域名邮箱` | `兰芯域名邮箱` |

迁移只使用上述非个人化的显示名称后缀规则；不得把真实姓名、邮箱、账号标识或其他个人数据写入仓库、测试夹具、迁移 SQL 或提交信息。当前线上清单中的全部记录均命中这些规则。

## 数据模型与迁移

### 固定字段

为 `account_assets` 追加 `asset_identifier` 列。应用层把它作为创建和编辑账号资产时的必填、非空白文本字段，最大长度沿用显示名称的 120 个字符限制。

迁移将已有记录的默认值设为明确的“未分类”，再按上表的显示名称后缀规则覆盖为已确认的资产标识。这样即使生产数据在迁移前发生意外变化，也不会静默伪造资产归属：未匹配的旧记录会显式显示为“未分类”，可由管理员在编辑面板中补正。

### 追加字段的弃用

- 保留 `account_field_definitions` 与 `account_field_values` 两张历史表，且不删除已有行。
- 页面移除追加字段表单、说明和任何可编辑入口。
- `GET/POST /api/account-field-definitions` 与 `PUT /api/account-assets/:accountId/field-values` 统一返回 `410 Gone` 和明确的弃用说明，不再读取、新增或修改追加字段。
- 文档不再把追加字段列为账号资产的可用能力。

## 页面与交互

### 新增流程

管理员账号资产页顶部显示“＋ 新增账号资产”按钮。新增表单默认隐藏，点击按钮展开，再次点击收起；按钮同步维护 `aria-expanded`。该模式与已有订阅新增面板一致。

表单字段顺序为：显示名称、资产标识、账号标识、归属人员、到期日。所有现有安全提示继续明确禁止填写密码、验证码和密钥。

### 编辑流程

现有编辑面板保留，新增资产标识输入项。保存时与显示名称、账号标识、归属人员、状态、到期日和凭据库引用一起提交；凭据库引用继续不在清单中显示。

### 清单与筛选

账号资产清单的列顺序为：显示名称、资产标识、账号标识、归属人员、状态、到期日、创建时间、操作。

筛选区包含：归属人员、资产标识、状态和关键字。资产标识为由当前列表去重生成的下拉选项；关键字同时匹配显示名称、资产标识和账号标识。员工视图仍只展示本人资产，不展示管理员的新增、编辑和筛选入口。

## API 与审计

- `GET /api/account-assets` 在每个记录中返回 `asset_identifier`。
- `POST /api/account-assets` 要求 `display_name`、`asset_identifier`、`account_identifier_masked`；资产标识为空、全空白或超长时返回 400。
- `PUT /api/account-assets/:accountId` 支持更新 `asset_identifier`，并保持所有者存在性、日期与状态校验。
- 创建或更新审计事件包含资产标识，但不新增任何敏感账号值到审计详情。
- 角色控制不变：只有数据管理员能创建或编辑账号资产；已弃用接口对所有调用方均在读取或写入前返回 `410 Gone`。

## 错误处理与兼容性

- 旧记录若未匹配到回填规则，显示“未分类”，不会被错误地归入某个服务；管理员可在编辑面板修正。
- 新建或编辑时缺少资产标识，后端拒绝请求，不允许浏览器绕过校验。
- 追加字段端点返回可读的弃用错误；旧客户端不会误以为数据已保存。
- 迁移不删除或改写账号标识、归属人员、状态、到期日、凭据库引用或历史追加字段值。

## 验证策略

- Schema/migration 测试：新列存在；各已确认的非个人化命名模式均回填为正确资产标识；未匹配记录保持“未分类”。
- API 测试：创建、读取和更新资产标识；空白值被拒绝；追加字段接口不能再写入。
- UI 测试：新增面板默认隐藏且可切换；追加字段 UI 不存在；清单显示资产标识列；资产标识下拉筛选和关键字筛选生效。
- 回归测试：执行完整 Vitest 测试、TypeScript 类型检查和 Worker dry-run build。

## 部署边界

生产上线前必须先确认远程 D1 migration 状态与 Wrangler 凭据，再按“远程 migration 先于 Worker 部署”的顺序执行。此实现仅提供代码、迁移与验证证据，不会自行触发生产数据库写入或部署。
