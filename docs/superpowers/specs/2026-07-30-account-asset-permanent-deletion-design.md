# 账号资产永久删除设计

## 背景

账号资产已具备新增、编辑、筛选和只读查看能力，但管理员无法清理已废弃或误建的记录。用户已确认需要不可恢复的永久删除，而不是把记录标记为已退役或放入回收站。

历史动态追加字段功能已退役，相关表仍保留既有数据。`account_field_values` 通过外键关联 `account_assets`，因此永久删除资产时必须先删除该资产的关联历史字段值，否则数据库会拒绝删除父记录。

## 目标

- 让 `system_admin` 和 `asset_admin` 能永久删除单个账号资产。
- 删除时同时清理该资产的历史 `account_field_values` 记录。
- 对每次成功删除保留不含敏感账号数据的审计记录。
- 在管理员清单提供清晰、不可误解的二次确认交互。
- 保持员工、审计、财务等只读角色不能看到或调用删除能力。

## 非目标

- 不提供撤销、恢复、回收站或软删除机制。
- 不删除 `account_field_definitions`；它们可能仍被其他历史资产值引用。
- 不删除、导出或记录密码、验证码、令牌等凭据。
- 不改变账号资产的创建、编辑、筛选、所有权或员工可见范围。
- 不自动执行远程数据库迁移、部署或生产数据写入。

## 已确认决策

删除采用不可恢复的物理删除。删除账号资产时，系统会先移除其全部遗留 `account_field_values`，然后移除资产记录本身。成功删除后只留下安全审计事件；该审计事件不包含账号标识、归属人员、凭据库引用或任何凭据。

这是一项针对明确删除请求的例外：常规迁移与追加字段弃用仍保留历史表和数据，但管理员主动永久删除某一资产时，其从属的历史字段值随之销毁。

## 接口与数据处理

新增 `DELETE /api/account-assets/:accountId`。

- 权限与新增、编辑复用 `DATA_ADMIN_ROLES`，仅允许 `system_admin` 和 `asset_admin`。
- 现有的变更请求 Origin 防护继续适用。
- 处理前只读取删除所需的安全快照：`id`、`display_name`、`asset_identifier`、`status`。
- 资产不存在时返回 `404`，错误码为 `account_asset_not_found`，不创建审计事件。
- 成功时按子表到父表的顺序处理：删除匹配资产 ID 的 `account_field_values`，删除 `account_assets`，写入审计事件；这些数据库操作放在同一 D1 批处理中，并且只有全部成功才返回成功响应。
- 成功响应为 `{ account_asset_id, deleted: true }`，状态码为 `200`。

审计事件固定使用：

- `action`: `delete_account_asset`
- `entity_type`: `account_asset`
- `entity_id`: 被删除资产 ID
- `detail_json`: 仅包含 `display_name`、`asset_identifier`、`status`

审计详情不得包含 `account_identifier_masked`、`owner_user_id`、`owner_name`、`vault_ref`，也不得通过数据库错误或响应向浏览器泄露这些字段。

## 页面与交互

管理员账号资产清单的每一行操作列新增红色“删除”按钮，使用现有样式系统中的危险操作外观。按钮和相关脚本必须仅在服务端确认 `canManageAccounts` 时输出。

点击后显示浏览器二次确认，明确展示显示名称并说明“此操作不可恢复”。用户取消时不发送请求。

确认删除后：

1. 立即禁用该行删除按钮，避免重复提交。
2. 发送 `DELETE /api/account-assets/:id`。
3. 成功时显示删除成功提示、刷新清单；如果当前编辑的正是该资产，隐藏并重置编辑面板。
4. 失败时显示后端提供的安全错误消息，并重新启用按钮。

`employee`、`auditor`、`finance_reviewer`、`payer` 以及无角色用户保持只读：渲染结果不得包含删除按钮、删除动作标识、删除 API 路径或删除处理脚本。

## 错误处理与边界

- 未登录、角色不足或 Origin 不被允许的请求沿用现有认证和 Origin 防护响应，且不执行数据库删除。
- 找不到资产时安全返回 404；重复删除同一 ID 的后续请求也返回该错误。
- 若数据库操作失败，接口不返回成功；浏览器保留当前清单并允许用户重试。
- 删除前不把完整资产对象传入审计详情或提示文案；页面确认只使用显示名称。
- 不增加数据库迁移，因为删除行为使用已有表与外键关系。

## 验证策略

- API 测试：两类数据管理员可删除；只读角色被拒绝；缺失资产返回 404；关联 `account_field_values` 被清理；父资产被清理；重复删除不产生额外审计；审计详情精确包含允许字段且不包含敏感字段。
- UI 测试：管理员文档包含删除按钮、确认文案、`DELETE` 请求、请求中禁用、失败恢复、成功刷新与编辑面板清理；只读角色的 HTML 和脚本不包含删除契约。
- 回归验证：运行完整 Vitest 测试、TypeScript 类型检查、Worker dry-run build 和 diff 检查。

## 部署边界

此功能不需要 D1 migration。部署仍必须在本地验证、提交和用户明确授权后执行；不得因为代码完成而自动推送 Git 远端或更新生产 Worker。
